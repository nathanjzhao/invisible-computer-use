## Broad TCC management and consent UI

Codex/Sky manages far more privacy scopes than a computer-use driver strictly needs, and wraps them in a real consent product: a catalog-driven permission window plus an "accessory" overlay that animates onto System Settings and highlights the exact toggle the user must flip. cua-driver gates exactly two TCC grants (Accessibility + Screen Recording) through a simple NSPanel and a deep-link. The extra Codex scopes exist for ChatGPT's native app tools (Contacts/Calendar/Reminders/Messages/Location), not for the CUA loop itself, so most of the breadth is out of scope for a generic driver; only the guided-consent UX is a candidate to copy.

### Codex/Sky

- ChatGPT `Info.plist` declares 10 usage-description strings (`plutil -p /Applications/ChatGPT.app/Contents/Info.plist | grep UsageDescription`): `NSAppleEventsUsageDescription`, `NSAudioCaptureUsageDescription`, `NSCalendarsFullAccessUsageDescription`, `NSCalendarsUsageDescription`, `NSCameraUsageDescription`, `NSDesktopFolderUsageDescription`, `NSLocationUsageDescription`, `NSMicrophoneUsageDescription`, `NSRemindersFullAccessUsageDescription`, `NSRemindersUsageDescription`. CONFIRMED.
- Native service `SkyComputerUseService` embeds 9 distinct System Settings privacy anchors (`strings ... | grep -oE 'Privacy_[A-Za-z]+' | sort -u`): `Privacy_Accessibility`, `Privacy_AllFiles` (Full Disk Access), `Privacy_Automation`, `Privacy_Calendars`, `Privacy_Camera`, `Privacy_Contacts`, `Privacy_Location`, `Privacy_Reminders`, `Privacy_ScreenCapture`. CONFIRMED.
- SlimCore models a permission-protocol hierarchy, not a hardcoded pair: symbols `$s8SlimCore16SystemPermissionP`, `$s8SlimCore25TCCDialogSystemPermissionP`, `$s8SlimCore31SystemSettingsPrivacyPermissionP`, `$s8SlimCore21AppleEventsPermissionP`, plus concrete `AccessibilityPermission`, `RemindersPermission`, `CalendarPermission`, `ContactsPermission`, `CalendarAppleEventsPermission`, `AppleEventsPermission`, and status types `SystemPermissionStatus` / `SystemSettingsPrivacyPermissionError`. CONFIRMED.
- Consent UI is catalog-driven: `PermissionCatalog`, `ComputerUse.PermissionWindowController` (`_TtC11ComputerUse26PermissionWindowController`), `PermissionRowRegistry` + nested `PermissionRowRegistry.Entry`, `PermissionViewState`, `InProgressPermissionRowButtonStyle`, `InProgressPermissionRowPlaceholder`, and `Codex_Computer_Use.CUAServicePermissionState`. Row label string `Full Disk Access` present. CONFIRMED.
- The guided "accessory overlay" lives in SlimCore (`SlimCore/SystemSettingsAccessCoordinator.swift`, `SlimCore/SystemSettingsAccessoryWindow.swift`, `.../SystemSettingsAccessoryWindowView.swift`, `.../SystemSettingsAccessoryTransitionOverlayWindow.swift`): classes `SystemSettingsAccessCoordinator`, `SystemSettingsAccessoryWindow`, `SystemSettingsAccessoryTransitionController`, `SystemSettingsAccessoryTransitionOverlayWindow`; behavior flags `shouldActivateSystemSettingsAfterAccessoryPresentation`, `shouldPresentAccessoryWithoutTransition`; highlight API `highlight:withFrame:inView:`; user-facing string `COMPLETE IN SYSTEM SETTINGS`. This is the overlay that transitions onto Settings and points at the toggle. CONFIRMED.
- Telemetry confirms it is a tracked funnel: `AnalyticsEvents_V1_CodexComputerUsePermissionWindowShown`, `...PermissionRequested`, `...PermissionGrantFinished`, `CodexPermissionRequestAutoDenied`, `CodexComposerPermissionsModeChanged`. Conversational onboarding access types enumerate the app-tool scopes: `CODEX_CONVERSATIONAL_ONBOARDING_ACCESS_TYPE_{COMPUTER_USE,CALENDAR_APP,MESSAGING_APP,DESKTOP,CSV_PICKER}`. CONFIRMED.
- The CUA loop itself only blocks on the same two grants as cua: sky JS error codes `permissionsNotGranted:-10009` and `permissionsPending:-10014` (`.../sky_js/src/targets/mac/errors.js`), and the native pending message names only "Accessibility and Screen Recording" ("Computer Use permissions are still pending... has not finished granting Accessibility and Screen Recording..."). So the other 7 scopes gate app tools, not computer use. CONFIRMED / INFERRED (the mapping of extra scopes to app tools is inferred from the ContactsCore/MessagesCore/Calendar symbols and onboarding access types).

### cua-driver

- `rust/crates/platform-macos/src/permissions/status.rs` — `struct PermissionsStatus { accessibility: bool, screen_recording: bool }`, `current_status()`, `all_granted()`. Probes are `AXIsProcessTrusted()` and `CGPreflightScreenCaptureAccess()`. Exactly two scopes. CONFIRMED.
- `rust/crates/platform-macos/src/permissions/gate.rs` — `enum MissingPermission { Accessibility, ScreenRecording }` with `settings_url()` returning `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` and `?Privacy_ScreenCapture`. No other variants. CONFIRMED.
- `rust/crates/platform-macos/src/permissions/panel.rs` — native `NSPanel` (`PanelOutcome`, `show_modal`) with two status rows, 1 Hz `NSTimer` polling, "Open Settings" / "Continue anyway" buttons. It opens the pane but does not overlay or highlight the toggle. CONFIRMED.
- `rust/crates/platform-macos/src/permissions/mod.rs` — module doc states scope plainly: "low-level booleans for Accessibility / Screen Recording". CONFIRMED.
- Full Disk Access, Contacts, Calendar, Reminders, Location, and an Automation/AppleEvents TCC gate: absent. Searched all of `rust/` for `FullDiskAccess|Privacy_AllFiles|CNContact|EKEvent|EKReminder|Privacy_Automation|Privacy_Contacts|Privacy_Calendars|Privacy_Reminders|Privacy_Location` — the only hits are `NSAppleEventDescriptor` in `apps/nsworkspace.rs` (used to send an open-application Apple Event, no TCC gate around it) and an `NSAppleEventsUsageDescription` string in `scripts/CuaDriverBundle/Contents/Info.plist`. The bundle plist declares only `NSScreenCaptureUsageDescription` and `NSAppleEventsUsageDescription`. CONFIRMED.
- `rust/crates/platform-macos/src/permission_observation.rs` is unrelated to TCC breadth: it is a `DirectCaptureEvidenceStore` recording a signed JSON note that a direct-capture grant was verified for `com.trycua.driver`. Not a consent UI or a scope manager. CONFIRMED.

### Delta

- Matches: both deep-link into the correct pane via the `x-apple.systempreferences:com.apple.preference.security?Privacy_*` scheme; both run a live-polling status surface (Codex `PermissionWindowController` / `PermissionRowRegistry` vs cua `panel.rs` NSPanel at 1 Hz); both treat Accessibility + Screen Recording as the two grants that actually block the computer-use loop.
- Codex-ahead: (1) breadth — 9 TCC scopes and a `PermissionCatalog`/`SystemPermission` protocol model vs cua's hardcoded 2-variant enum; (2) guided consent — the `SystemSettingsAccessCoordinator` + `SystemSettingsAccessoryWindow` overlay that transitions onto System Settings and highlights the exact toggle ("COMPLETE IN SYSTEM SETTINGS"), vs cua merely opening the pane; (3) a tracked grant funnel with analytics and an auto-deny path.
- cua-ahead: nothing here. cua's only adjacent extra is the `DirectCaptureEvidenceStore` provenance record, which Codex has no visible analogue for.

### Recreate / port plan

- Scope decision first. A generic computer-use driver needs Accessibility (AX tree + synthetic input) and Screen Recording (per-window capture) — cua already has both. The other Codex scopes map to ChatGPT's native app tools: Contacts/Calendar/Reminders/Location/Messages and Desktop/Full Disk/CSV picker. Those are app-integration features, not driver primitives. Do NOT add Contacts/Calendar/Reminders/Location gates; they are non-goals for cua-driver.
- Two scopes are arguably in-scope later and cheap to add if a feature demands them: Automation/AppleEvents (cua already sends an open-application Apple Event in `apps/nsworkspace.rs` and declares `NSAppleEventsUsageDescription`, but has no `Privacy_Automation` gate or preflight) and Full Disk Access (only if the driver ever reads TCC-protected files). Hook point: extend `MissingPermission` in `gate.rs` with `Automation` / `FullDiskAccess` variants and their `settings_url()` anchors (`?Privacy_Automation`, `?Privacy_AllFiles`), and add matching probes in `status.rs`. There is no clean public preflight for Automation, so this is effort out of proportion to value until a tool needs it — defer.
- The one genuinely worth-copying piece is the guided-consent overlay. cua's `panel.rs` opens the pane and leaves the user to hunt for the row; Codex animates an accessory window over Settings and highlights the toggle. Hook point: a new `permissions/accessory.rs` alongside `panel.rs`, driven from the "Open Settings" branch of `PanelOutcome`, using an `NSWindow` overlay positioned over the Settings pane (mirror of `SystemSettingsAccessoryTransitionOverlayWindow` + `highlight:withFrame:inView:`). This is native AppKit work on the same main-thread run loop the cursor overlay already uses, so it is a native-patch, not a rewrite.
- Should we build it: skip the breadth (non-goal, it is ChatGPT app surface). The accessory overlay is a real UX win but pure polish — worth it only if onboarding friction is a measured problem; the existing NSPanel + deep-link already unblocks the user. Recommend: keep 2 scopes, optionally add the accessory overlay when onboarding polish is prioritized.
