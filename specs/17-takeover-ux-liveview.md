## Takeover UX and live view: Appshot, SkyLens, Remote PiP, multi-cursor

The visible "Codex is taking control" surface beyond the moving pointer: a shutter-style capture transition when a window is attached (Appshot), an animated glow/lens overlay around the acting cursor (SkyLens), a floating live mirror of the controlled window (Remote-hosted PiP), a registry of per-app cursors (ComputerUseCursor.all), and a "close enough" targeting tolerance so the cursor stops short of pixel-perfect. All five live in the native `SkyComputerUseService` binary; cua-driver has a cursor overlay with a single-rect element highlight and a screenshot-slideshow PiP, and matches only the multi-cursor registry piece. CONFIRMED via `strings` + `nm | swift demangle` on the service binary, and file reads on both trees.

### cua-driver

- **Element highlight flash: present but static** (`rust/crates/cursor-overlay/src/render_state.rs`). `pub struct FocusRect` (render_state.rs:746), painted in `render_frame` when the caller supplies one; comment at :826 "Focus rect highlight (macOS only) - Cyan glow border + faint fill, matching Swift AgentCursor.showFocusRect." This is a single post-arrival rectangle, not a 45-frame animated lens sequence. `OverlayCommand::ShowFocusRect` exists (:736).
- **Cursor motion / pulse / glow** (`cursor-overlay/src/render_state.rs`, `theme.rs`). `ClickPulse` phase animation (render_state.rs:469-471, "full pulse over 0.25s"), spring settle, idle-fade, and a themed white-outline + glow silhouette (theme.rs:304 `matching_glow_surrounds_the_full_pointer_silhouette`). No shutter/magic-move capture transition analog: **Appshot is absent** (searched `cursor-overlay/`, `platform-macos/`, no `appshot`/`magicMove`/`CaptureTransition` symbols).
- **Multi-cursor registry: present** (`cursor-overlay/src/lib.rs`). `CursorConfig.cursor_id` (defaults `"default"`) and `all_states() -> Vec<CursorInstanceState>` (lib.rs:276) are the direct analog of `ComputerUseCursor.all`. Exercised by `cua-driver/tests/agent_cursor_windows_test.rs` with distinct `cursor_id` values.
- **PiP: present but a screenshot slideshow, not a live stream** (`rust/crates/cua-driver-core/src/pip_hook.rs`, `rust/crates/platform-macos/src/pip/mod.rs`, `rust/crates/pip-preview/src/lib.rs`). `pip_hook::push_pip_frame(PipHookFrame { png_bytes, action_label, timestamp_ms })` is called by the tool dispatcher after each successful tool call; `MacosPipBackend::push_frame` (pip/mod.rs) builds an `NSImage` from the PNG and sets it on a floating `NSWindow` + `NSImageView` with a one-line `NSTextField` label. Gated by `--experimental-pip` / `experimental_pip` config (pip-preview/src/lib.rs:84-192). No ScreenCaptureKit, no XPC content host, no per-window geometry tracking, no in-PiP cursor, no checkerboard fallback: it shows the last captured screenshot, updated per action.
- **Close-enough targeting: absent** as an explicit config. Path planner (`cursor-overlay/src/path_planner.rs`) drives glides to the exact target; no `distanceThreshold`/`progressThreshold` early-stop analog found.

### Delta

- **Matches**: multi-cursor registry (`ComputerUseCursor.all` <-> `all_states()` + `cursor_id`); a post-arrival element highlight (SkyLens <-> `FocusRect`, both explicitly "matching Swift AgentCursor.showFocusRect"); click-pulse and glow silhouette on the cursor itself.
- **Codex ahead**: (1) Appshot magic-move capture transition, an entire subsystem (~299 symbols, shutter/snapshot/shadow/title/icon layers, sound, magic-move handshake) with no cua analog. (2) SkyLens as a 45-frame prerendered animated glow vs cua's single static rectangle. (3) Remote-hosted PiP is a live ScreenCaptureKit window mirror with in-PiP virtual cursor, geometry tracking, XPC content hosting, and checkerboard fallback (~269 symbols) vs cua's static per-action screenshot in an NSImageView. (4) CloseEnoughConfiguration targeting tolerance.
- **cua ahead**: nothing material in this surface. (cua's themable compiled-cursor artifact system is richer but belongs to the cursor-rendering section, not takeover UX.)

### Recreate / port plan and "should we even build this" call

- **Appshot capture transition: skip (non-goal).** It is ChatGPT-app-specific UX tied to the "+ menu / both-command-keys" attach gesture and app-icon/title chrome, and its sole job is telling a human "this window is now attached." A generic driver invoked over MCP has no attach gesture and no app-branded surface to shutter into. Porting it is pure cosmetics with an app-shaped dependency. Do not build.
- **SkyLens-style highlight flash: cheap polish, worth it.** cua already has the hook (`OverlayCommand::ShowFocusRect` -> `FocusRect` painted in `render_frame`). Upgrade path is small and local: drive the existing `FocusRect` alpha/scale over ~0.3s from the render loop the same way `ClickPulse` phase is advanced (render_state.rs:469), rather than porting the 45 PNGs. Hook point: add a `focus_flash: Option<f32>` phase alongside the click-pulse field and blend it in the :826 focus-rect block. This closes the animation gap without shipping a frame bundle.
- **Remote-hosted live PiP: the one genuinely worth considering, but it is a large build.** cua's PiP is a screenshot slideshow because it reuses the recorder's PNG callback (pip_hook.rs). A live view means a `platform-macos` ScreenCaptureKit `SCStream` bound to the controlled `windowID`, its `CMSampleBuffer`s driven into an `AVSampleBufferDisplayLayer`, plus geometry/occlusion tracking and the virtual cursor composited on top. That is essentially the whole `RemoteHostedPIPWindowRenderer` (269 symbols) minus the XPC split, which cua can drop since it is single-process. Hook point: a new `PipBackend` impl behind the existing `pip-preview::PipBackendFactory` / `--experimental-pip` flag, so nothing above the backend changes. Recommend building only if a human-in-the-loop "watch it work" view is a product goal; for a headless/CI driver it is not worth the ScreenCaptureKit surface.
- **CloseEnoughConfiguration: optional small add.** A `distance_threshold`/`progress_threshold` early-stop in `path_planner.rs` would make glides look less robotic on long moves. Low value, low cost; bundle it with the highlight-flash work if touching the overlay anyway.
