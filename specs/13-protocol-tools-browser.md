## Transport, tool surface, and browser CDP path

### What it is

The wire between the agent runtime and the native computer-use service, the shape of the tool/action surface exposed over that wire, and the mechanism each system uses to drive a real browser. cua-driver is an MCP server: newline-delimited JSON-RPC 2.0, a generic `tools/list` registry, and a browser subsystem that attaches to Chrome over loopback CDP. Codex/Sky is a length-prefixed JSON-RPC pipe to a single Swift service exposing a fixed set of typed IPC action structs, with the browser driven through a Chrome extension rather than CDP.

### Codex/Sky

Sky's transport is a length-prefixed JSON-RPC 2.0 client over an App-Group unix socket, talking to one auto-launched Swift service (`SkyComputerUseService`). The tool surface is not a discoverable registry; it is a closed set of typed `ComputerUseIPC*` request structs. The browser is handled by a Chrome extension, not CDP.

- `dist/project/cua/sky_js/src/targets/mac/native-pipe.js` — `MacNativePipeTransport`. Frame codec `encodeMessageFrame`/`decodeMessageFrames`: a 4-byte little-endian `UInt32LE` length prefix then UTF-8 JSON, cap `k = 8388608` (8 MiB). Socket path `~/Library/Group Containers/2DC432GLL2.com.openai.sky.CUAService/IPC/computeruse.sock` (override `SKY_CUA_SERVICE_NATIVE_PIPE_PATH`). Two JSON-RPC methods only: `ping` (params `{clientApiVersion}`) whose reply must satisfy `serverApiVersion === clientApiVersion` or it throws a version-mismatch (`class D extends c`); and `request` (params `{clientApiVersion, codexTurnMetadata, deadlineUnixMilliseconds, request, requestType}`). Numeric monotonic ids, per-id oneshot map, per-call timeouts. If the pipe is down it calls `ensureService` over `NODE_REPL_HOST_SERVICES_PIPE_PATH` or `launchServices.openApplication` of `Codex Computer Use.app` (bundle `com.openai.sky.CUAService`).
- `dist/project/cua/sky_js/src/targets/mac/client.js` — the typed action set carried in `request` with `requestType`: `ComputerUseIPCAppGetSkyshotRequest` (state/screenshot), `ComputerUseIPCListAppsRequest`, `ComputerUseIPCAppStartRequest` (launch), `ComputerUseIPCAppPolicyRequest`, audio start/stop, and `ComputerUseIPCAppPerformActionRequest` wrapping one of `click | drag | paste | performSecondaryAction | pressKey | scroll | setValue | selectText | typeText`. Targeting is by `elementIndex`/`elementID` (the Skysight accessibility index) plus `x,y` and `app` — an OS-accessibility handle, not a DOM ref. `requestType:"jsonRPC"` is the transport-level tag.
- `dist/project/cua/sky_js/src/targets/mac/click.js` — one action shape: `e.click({app, clickCount, elementIndex, mouseButton, x, y})`, gated through `withComputerUsePolicy("click", ...)`.
- `dist/project/cua/sky_js/src/sky.js` — hard dependency on the trusted host runtime: `throw new Error("sky requires node_repl; configure NODE_REPL_TRUSTED_SERVICES")`. `node_repl`/`nodeRepl` is the ChatGPT-app bridge providing `nativePipe`, `launchServices`, and turn metadata; it is not itself a model-facing tool. `cua_repl` was **not found** anywhere under `dist/project/cua/sky_js/src` (grep, 0 hits).
- `Codex Computer Use.app/Contents/MacOS/SkyComputerUseService` (22.9 MB Mach-O arm64) — `strings` shows **no** CDP/DevTools tokens at all (`devtools`, `remote-debugging`, `webSocketDebuggerUrl`, `Target.attach`, `Input.dispatch`, `Runtime.evaluate` all 0 hits). Instead: `ChromeExtensionInstaller`, `_isChromeExtensionInstalled`, `GetTabContext`, `_isBrowserUseTab`, `## Browser Computer Use`, `Add to Chrome`. Browser tab context and browser-use come from a Chrome extension; page actions still ride the accessibility/Skysight layer. Confirmed by corpus: `codex-corpus/mac/ComputerUse/SkysightSummarizer.md` treats "browser content" as untrusted observed AX/text, never a CDP-driven DOM.
- `package.json` — `@oai/sky` 0.6.26, exports `./service`, ships `bin/mac/{normal,relaxed}/Codex Computer Use.app` bundles (service + installer + client + lock-screen guardian).

### cua-driver

cua-driver is a standards-shaped MCP server. A generic `ToolRegistry` answers `initialize` / `tools/list` / `tools/call`; the same dispatch is reused across a stdio proxy, a UDS daemon, and an HTTP listener. Framing is newline-delimited JSON everywhere (no length prefix). The browser subsystem is a first-class CDP client that attaches to a real Chrome over a loopback WebSocket.

- `rust/crates/cua-driver-core/src/protocol.rs` — MCP JSON-RPC types: `Request`/`Response`/`ResponseBody`/`ToolResult`/`Content`. `initialize_result()` advertises `protocolVersion "2025-06-18"`, `serverInfo {name:"cua-driver"}`, and a compact `instructions` string. `Request::tool_call()` splits `{name, arguments}`.
- `rust/crates/cua-driver-core/src/server.rs` — `handle_request` / `handle_request_inner` dispatch against the `ToolProvider` trait (implemented by `ToolRegistry`). Injects `_session_id` / `_transport_session_id` from the public `session` arg or a trusted transport lease, calls `sanitize_reserved_args`, and authorizes via `authorize_tool_call`. Also a large privacy-bounded telemetry layer (`ToolCompletionObservation`, `tool_operation`, refusal-code allowlist) that never retains argument content.
- `rust/crates/cua-driver-core/src/tool.rs` — `ToolRegistry` (`HashMap<String,Box<dyn Tool>>` + `order: Vec`), `register`, `tools_list` (emits `{tools, capability_version, schema_version, enforcement_adapters}`), `ToolDef { name, description, input_schema, read_only, ...annotations }` → `to_list_entry`. `invoke_from_trusted_adapter` pulls `TrustedInvocationEvidence` (`_session_id`, `_transport_session_id`, download approval) then strips underscore args.
- `rust/crates/cua-driver-core/src/tool_schema.rs` — shared JSON-Schema fragments (`session_schema`, `delivery_mode_schema`, `element_token_schema`, ...) and `shared_schema_violations`, a cross-platform gate enforcing identical param shapes.
- `rust/crates/cua-driver-core/src/tool_args.rs` — `ArgsExt` typed accessors, `parse_typed_input`/`parse_typed_projection`, and `sanitize_reserved_args` (drops all `_`-prefixed keys so callers can't forge transport evidence).
- `rust/crates/cua-driver-core/src/daemon.rs` — the daemon wire protocol: `DaemonRequest`/`DaemonResponse`, `DaemonMetadata` version handshake (`request_daemon_metadata`), `socket_path_for_namespace` (`~/Library/Caches/<ns>/<ns>.sock` on macOS), and `send_request` (newline-framed, retries transient timeouts to a 120s deadline).
- `rust/crates/cua-driver-core/src/socket_io.rs` — `write_all_with_retry`, EAGAIN/`WouldBlock` retry so a busy daemon isn't a fatal transport error.
- `rust/crates/cua-driver/src/proxy.rs` — stdio MCP adapter. `run_direct` reads JSON-RPC lines from stdin (`reader.read_line`), calls `handle_request_with_transport_session`, writes one line per response, EOF ends the session. `run_proxy` forwards to the daemon over UDS.
- `rust/crates/cua-driver/src/serve.rs` + `main.rs` — the `UnixListener` daemon (`BufReader::...lines()`, one `DaemonRequest` per line) and the mode selection (`run_mcp_direct` vs proxy vs daemon). `rust/crates/cua-driver/src/mcp_http.rs` — a third transport: `POST /mcp` with a JSON-RPC body → same `handle_request`, `application/json` reply, loopback-only, browser-origin requests rejected.
- `rust/crates/cua-driver-core/src/browser/mod.rs` — exact-or-refused binding model. Native entrypoint `pid + window_id`; opaque session-scoped refs `p<snapshot>:<index>`; refusals carry stable `BrowserRefusalCode`s. Registers `browser_prepare`, `get_browser_state`, `browser_click`, `browser_type`, `browser_pointer`, `browser_dialog`, `browser_set_input_files`, `browser_download`.
- `rust/crates/cua-driver-core/src/browser/cdp_ws.rs` — pooled event-aware CDP WebSocket demultiplexer (`CdpConnection`). `validate_loopback_ws_url` accepts only `ws://` on `127.0.0.1`/`::1`/`localhost`. `CdpMethodPolicy::ExistingProfile` restricts a grant-owned personal-profile socket to a ~30-method allowlist (`Target.attachToTarget`, `Input.dispatchMouseEvent`, `Runtime.callFunctionOn`, `DOM.getDocument`, ...).
- `rust/crates/cua-driver-core/src/browser/prepare.rs` — `attach_existing_profile`; isolated launch with `--remote-debugging-port=0`, `wait_for_spawned_endpoint` scraping `/devtools/browser/...`, then `attest_spawned_endpoint` against live loopback socket ownership.
- `rust/crates/platform-macos/src/browser/platform.rs` — the macOS existing-profile attach: `discover_owned_endpoint`, `setup_ui::enable` to turn on remote debugging via the browser's own UI, `active_port_endpoint`, `loopback_ports_for_pid` (lsof), `parse_devtools_active_port`, and `OwnedEndpoint` + `EndpointOwnershipProof { method: ListeningSocketPid }` correlating the new PID-owned listener to the exact approved window.
- `rust/crates/platform-macos/src/browser/cdp_client.rs` — legacy CDP client for Electron/Chromium. `/json` HTTP discovery, classic `webSocketDebuggerUrl` vs `ws://host:port/devtools/browser` endpoints, and `CdpSessionCache` that reuses one approved connection to avoid re-triggering Chrome's "Allow remote debugging?" popup per call.
- `rust/crates/platform-macos/src/browser/ax_page_reader.rs` — `AXPageReader`, the accessibility-tree fallback that extracts page text/elements from AX markdown when CDP is not in play. This is the nearest thing to Sky's default browser path.

### Delta

| Aspect | cua-driver | Codex/Sky |
|---|---|---|
| Framing | Newline-delimited JSON (stdio, UDS, HTTP) | 4-byte LE length-prefix + JSON |
| Protocol | MCP JSON-RPC 2.0, `initialize`/`tools/list`/`tools/call` | JSON-RPC 2.0, only `ping` + `request` |
| Socket | `~/Library/Caches/<ns>/<ns>.sock` (per-namespace) | App Group `.../2DC432GLL2.com.openai.sky.CUAService/IPC/computeruse.sock` |
| Version handshake | `initialize` + `DaemonMetadata` (multi-field, tolerant) | `ping` with hard `serverApiVersion === clientApiVersion` lock |
| Tool surface | Open, discoverable registry + JSON schema per tool | Closed, typed `ComputerUseIPC*` action structs |
| Element targeting | pid+window_id, opaque CDP/DOM refs, AX `element_token` | Skysight accessibility `elementIndex`/`elementID` |
| Browser | Real loopback CDP attach (existing profile or isolated), method allowlist, exact-or-refused binding | Chrome extension for tab context; actions via accessibility. No CDP. |
| Transports | stdio + UDS daemon + HTTP `/mcp` | single native-pipe UDS |

- **Matches:** both are JSON-RPC 2.0 over a local unix socket to an out-of-process native service; both auto-launch/ensure that service; both carry per-turn metadata and per-call deadlines; both treat browser/page content as untrusted.
- **cua is ahead:** true CDP browser control (navigation, typed DOM refs, dialogs, downloads, file inputs, OOPIF) versus Sky's extension-plus-accessibility browser; an open, versioned, schema-described tool registry; three interchangeable transports; length-safe reasoning is unnecessary because framing plus a strict privacy seam is already built.
- **Codex is ahead:** length-prefixed framing removes the newline-in-payload hazard cua's line protocol carries; one App-Group service with a single strict version gate is simpler to reason about than cua's proxy/daemon/http fan-out; the fixed typed action set is smaller and harder to misuse; Skysight accessibility targeting needs no browser cooperation at all.

### Recreate/port plan

Goal: make cua present Codex's transport and action ergonomics while keeping (or optionally shadowing) cua's stronger CDP browser.

1. **Length-prefixed App-Group transport adapter** — add a `sky_pipe.rs` transport beside `rust/crates/cua-driver/src/proxy.rs` that frames with a 4-byte `u32` LE prefix (mirror `encodeMessageFrame`/`decodeMessageFrames`) and binds the App-Group socket path. It decodes the outer `{method, params}` and routes `request.params.request` into `cua_driver_core::server::handle_request_with_transport_session`. **thin-port** (the codec is ~30 lines; reuse existing dispatch).
2. **`ping`/version handshake shim** — in that adapter, answer `ping` with a `serverApiVersion` equal to the client's `clientApiVersion` expectation, matching `native-pipe.js` semantics. Wire it to `DaemonMetadata` for the real version. **thin-port.**
3. **`requestType` → tool mapping** — translate `ComputerUseIPCAppPerformActionRequest` variants (`click`/`scroll`/`typeText`/`drag`/`pressKey`/`setValue`/`selectText`/`paste`/`performSecondaryAction`) and `AppGetSkyshot`/`ListApps`/`AppStart` into cua tool names and args in the adapter. `elementIndex` maps to cua's `element_index` + `snapshot_id`/`element_token`. **native-patch** (needs a real translation table and arg reshaping; touches `tool_args.rs` conventions).
4. **Browser decision** — either (a) keep cua's CDP path unchanged and expose it under Sky action names, which is strictly more capable, or (b) if bug-for-bug Codex parity is required, thin-port an extension/accessibility reader on top of `platform-macos/src/browser/ax_page_reader.rs`. Recommend (a). **native-patch** if (a) is exposed under new names; **large-build** if (b) reproduces the extension.
5. **Corpus copy** — the per-app playbooks under `codex-corpus/mac/ComputerUse/AppInstructions/*.md` and `SkysightSummarizer.md` are prompt/behavior assets, not code; drop them into the cua skills tree as-is. **copy-verbatim.**

Net: transport + handshake + action mapping is a self-contained new adapter module (native-patch overall). The browser is where cua already wins, so recreating Codex there is a choice, not a requirement.
