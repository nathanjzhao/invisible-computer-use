## The done-bar (applies to EVERY slice — non-negotiable)

A slice is DONE only when all of these hold. "Compiles" and "green tests" are NOT done.

1. **Spec-faithful**: implemented to its `specs/NN` section and, where one exists, its `conformance/golden/*`. Verbatim strings (headers, tool names, error codes) copied, not paraphrased.
2. **Rigorously tested**: unit tests over real behavior, not a strawman. Each NEW guard is made to FAIL ON PURPOSE once (break the thing it guards, watch the test go red, restore) — record that you did it. No test that passes for the wrong reason.
3. **Real-data validated** where the slice consumes cua output: drive it against live `cua-driver` output (a resolvable window; Activity Monitor self-updates) and show the real result, not just synthetic fixtures.
4. **Conformance-green**: if the slice has a `conformance/` contract, `CONFORMANCE_TARGET=our` passes it, and target behavior is actually exercised where compared. Adapter-selected xfails document coverage only; they do not prove observed stock-driver failures.
5. **Honest limits documented**: anything INFERRED (not recoverable from binaries/goldens) is labeled as such in the source and the plan.
6. **Checkpointed**: update this file's status table + the project memory before moving on.

If a slice cannot meet the bar because it needs something unavailable, mark it **PARKED** with the exact blocker (below) — never fake it green.

### Slice 9 — Readiness/capabilities API + emitted error taxonomy (onboarding surface)
